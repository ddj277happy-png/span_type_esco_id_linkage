# 输入数据约定

> 本仓库的算法在 `pipeline/01_数据准备/_02_prep_spans.py` 里读取输入数据,这里说明输入 CSV 的格式要求。

## 1. 文件位置

把输入 CSV 放到 `input_data/` 下,**文件名不限**,`_02_prep_spans.py` 会自动找该目录下最新的 `.csv`:

```
span_type_esco_id_linkage/
└── input_data/
    ├── step3_skill_annotation_20260810_012339.csv    ← 自动识别(最新的)
    └── step3_skill_annotation_20260810_012339.json   ← 不用,仅保留
```

`input_data/` 在 `.gitignore` 里,不会被推到 GitHub,这样原始招聘数据保留在本地。

**显式指定**:如果 `input_data/` 下有多个 csv,可以用环境变量 `SKILL_CSV` 指定具体哪个:

```bash
# Linux / macOS
export SKILL_CSV=/path/to/your_annotation.csv

# Windows PowerShell
$env:SKILL_CSV = "D:\path\to\your_annotation.csv"

python pipeline/01_数据准备/_02_prep_spans.py
```

## 2. 必填列(11 列,顺序固定)

| # | 列名 | 类型 | 说明 |
|---|---|---|---|
| 1 | `id` | 整数 | 记录编号,主键,自增或任意唯一值 |
| 2 | `企业名称` | 字符串 | 招聘企业全称(算法里不直接用) |
| 3 | `招聘岗位` | 字符串 | 岗位名称(算法里不直接用) |
| 4 | `工作城市` | 字符串 | 工作所在城市(算法里不直接用) |
| 5 | `匹配的语言` | 字符串 | 该岗位要求的非通用语种,逗号分隔 |
| 6 | `标注文本` | 字符串 | 标注后的完整职位描述(含 `@@片段##[标签]` 标记,可为空) |
| 7 | `L` | 字符串 | 语言能力片段列表,**分号 `;` 分隔** |
| 8 | `K` | 字符串 | 知识片段列表,**分号 `;` 分隔** |
| 9 | `S` | 字符串 | 技能片段列表,**分号 `;` 分隔** |
| 10 | `T` | 字符串 | 通用能力片段列表,**分号 `;` 分隔** |
| 11 | `标注状态` | 字符串 | `成功` / `无标注内容` / 任意值 |

**列名必须完全匹配**(中文字符,不能改),因为 `_02_prep_spans.py` 是按列名读。L/K/S/T 四列可以为空字符串,但必须有这个列。

## 3. LKST 标注体系

参考 [Chinese-SkillSpan](https://example.com) 框架,采用 ESCO-1.20 平面标注政策(标签不重叠、不嵌套),把能力片段分四类:

| 标签 | 全称 | 定义 | 示例 |
|---|---|---|---|
| `[L]` | Language | 自然语言能力 / 证书 / 等级 / 使用(仅限自然语言) | 英语六级、日语 N2、普通话二甲、能用英语沟通 |
| `[K]` | Knowledge | 知识客体(学科/领域/规范/标准/法规/框架,名词本体) | 国际贸易、法律法规、IATF16949、供应链管理 |
| `[S]` | Skills | 可执行能力 / 方法 / 工具使用(动作过程;编程语言与工具归此类) | 开发、调试、翻译、市场调研、Excel、Python |
| `[T]` | Transversal | 跨岗位通用软能力 | 沟通能力、团队合作精神、抗压能力、学习能力 |

**判定规则**:

1. **平面标注**:不重叠、不嵌套;并列项逐一切分
2. **最小充分片段**:剥离"参与 / 负责 / 进行 / 熟悉 / 掌握 / 具备 / 良好 / 较强"等触发词或评价词
3. **K/S 语境**:名词本体在"了解 / 熟悉 / 具备…知识"语境多判 `[K]`;在"制定 / 设计 / 开发 / 调试 / 部署"等动作语境多判 `[S]`
4. **冲突兜底**:先按语境判定 K/S,仍冲突按优先级 **L > S > K > T**

## 4. 示例(虚构 1 行)

CSV 第一行(`input_sample.csv` 里的 1 行):

```csv
id,企业名称,招聘岗位,工作城市,匹配的语言,标注文本,L,K,S,T,标注状态
0,示例科技有限公司,海外销售经理,上海,"英语, 日语","能用@@英语##[L]与海外客户邮件@@沟通##[S],熟悉@@国际贸易##[K]和@@团队合作##[T]",英语,国际贸易,沟通,团队合作,成功
```

实际 `_02_prep_spans.py` 关心的是 L/K/S/T 四列(分号分隔)→ 去重成 unique (span, type) 池。其它列(`id`/`企业名称`/`招聘岗位`/`工作城市`/`匹配的语言`/`标注文本`/`标注状态`)在匹配阶段不用,**只在合并长表时通过 `id` 关联回去**。所以即使你只有 L/K/S/T 四列也能跑(其它列补空字符串即可),但要写长表就需要 `id`。

## 5. 数据规模建议

为算法能稳定工作,建议输入:

- **总记录数** ≥ 1,000 条(少于这个 unique span 池太小,匹配覆盖率低)
- **每条记录 L/K/S/T 总片段数** ≥ 5 条(否则空跑)
- **L/K/S/T 跨 4 个标签都要有** 至少各 100 条(否则某些桶无法验证)

本仓库的 5,140 条 / 90,625 标注是参考量级。

## 6. 怎么接入

```bash
# 1. 把你的 CSV 放到 input_data/
cp /path/to/your_annotation.csv input_data/step3_skill_annotation.csv

# 2. 跑数据准备(去重 → 31K unique 池)
python pipeline/01_数据准备/_02_prep_spans.py

# 3. 输出:data/spans_unique.csv(31K unique (span, type))
```

`_02_prep_spans.py` 接受 `input_data/step3_skill_annotation.csv`(可改脚本顶部的 `SRC` 变量),自动:
- 解析 L/K/S/T 四列,按分号切
- 去除空白
- 去重,产出 `data/spans_unique.csv`(列:`span, type`)

## 7. 怎么生成你自己的输入

如果你手里只有原始招聘描述(没标 LKST),需要先走一遍 LLM 标注。可以参考 [Chinese-SkillSpan 论文](https://example.com) 的 prompt 设计,用 DeepSeek / GPT / Claude 等 LLM 按 LKST 体系标注。

或者直接借用本仓库上游的标注方式:见 [Chinese-SkillSpan 仓库](https://example.com) 的 `extract` 模式。
